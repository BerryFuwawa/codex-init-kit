# 配置保存后，何时生效

适用于本地 2.3.1.5 的按需初始化。保存、文件检查、独立探针和当前运行实例验收分别报告。初始化不会为了展示“已生效”而自动重启桌面。

## 生效范围

| 项目 | 已确认的读取范围与最小操作 | 当前对话及优先级 | 尚未确认的部分 |
| --- | --- | --- | --- |
| config.toml | 桌面新会话准备流程会请求读取配置；模型、思考强度等默认值优先在新会话核对，不必先退出桌面 | 当前回合参数不因改文件而自动更换；启动参数、会话选择、项目配置、所选配置档可能覆盖用户全局值 | 外部文件变更的缓存刷新时点、每个功能开关（含记忆）的热加载、已有对话恢复后的具体行为未实机验收 |
| AGENTS.md | 官方规则在新运行开始时构建；可先用新会话核对规则装载 | 全局 AGENTS.override.md 可替代 AGENTS.md；项目层规则与更高优先级指令仍适用，已有上下文不会被文件替换 | 当前桌面版已有会话是否／何时重读、新会话是否复用缓存未实机验收 |
| .env | 读取该文件的新 CLI／组件才能获得新值；现有进程环境不会由保存文件自动更新 | 新对话可能复用现有 CLI；桌面主进程与 CLI 子进程的环境分开核对 | 当前启动链中继承环境与 .env 同名变量的优先关系待验证；不能保证 .env 会配置桌面 WebSocket |
| CLI 路径 | 核对用户环境变量、机器级回退和组件路径；下一次桌面创建 CLI 进程后再核对进程映像 | 用户路径优先于机器级回退是工具的保存状态判定；启动进程携带的环境可能不同。现有进程不会热切换 | 仅核对路径不代表当前实例已切换；此页尚不采集运行实例证据 |
| 浏览器补丁 | 新的浏览器组件进程执行入口时采用；先建立新连接并观察组件是否新建 | 已加载的模块不会随文件替换重载；不关闭 Chrome 标签页。替换文件仍沿用退出确认 | 桌面如何复用／重建组件待验证；需退出桌面时另行确认，不统一要求重启 |
| WebSocket | 本工具保存的是下次启动设置；“修复并启动 Codex”给新桌面主进程传入代理环境 | 只保存设置或 .env 不会向当前主进程注入变量；独立 WS 路线的分流仍保持原实现 | 启动成功不是 Dot 列表、读取或发送验收；恢复连接前需确认旧发送请求状态 |
| 启动保护 | 程序保存与登录任务注册分别核对；下一次符合触发条件的用户登录才运行维护 | 不因安装任务立刻执行维护；应用在运行时维护会跳过，不强制中断对话 | 注册核验不等于实际登录触发已测试 |

配置优先级应以对应 Codex 版本的解析结果为准：显式启动／会话参数、受信任项目层、所选配置档和用户全局默认值并不等价；组织强制要求可能进一步限制有效设置。本工具只修改自己管理的用户配置，保留其他键，不通过覆盖这些上层设置强行“生效”。官方文档中的最新配置档形式不作为旧版本支持证明。

依据：[官方配置说明](https://learn.chatgpt.com/docs/config-file/config-basic)、[官方 AGENTS.md 说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。本地还核对了桌面包 26.1111.2228.0 中的新会话配置读取、WebSocket 环境代理分支，以及工具本身的启动和任务实现；未对正在工作的真实会话做配置变更实验。

## 结果页

“本次变更何时生效”仅列出本次实际写入的项目，显示保存内容、生效方式、影响范围和核验程度。相同内容跳过，不重复显示为新变更。部分完成时保留成功写入的记录；仅重试失败项后继续保留前次记录。开始新的初始化操作才清空这组记录。

CLI 统一显示“已核对保存的 CLI 选择”“当前运行实例未核验”。组件的单独版本探针不冒充当前会话实际运行版本。浏览器隔离 Node 探针通过，也不冒充当前组件或 Chrome 已连通。

没有发生变更时，无需为本次检查重启；这不表示之前存在的连接问题已经解决。旧后台结果缺少变更信息时，不把缺失信息解释为没有变更。

## 最小验证方式

1. 先查看结果中的变化项；不变的配置和正常组件继续使用。
2. 模型、规则等先在新会话核对；如果有效值仍不同，再检查覆盖层和缓存，不先关闭所有对话。
3. 代理与 CLI 看实际运行进程，不能以工具保存状态替代。浏览器看新组件与真实操作，WS 看新桌面环境、握手及对应客户端结果。
4. 确实需要重新打开桌面时，先保存其他对话，并取得本次关闭授权。尚未确认结束的远程发送不重发，也不靠重启“试试看”。

## 完整初始化的关闭与启动

完整初始化会在开始前确认关闭 Codex，再执行差异检查与准备；这与单独维护或失败项重试的按需关闭不同。WebSocket 准备完成后，从结果页点击“启动 Codex（使用本次代理）”，给新的桌面进程传入代理并读取保存的 CLI 路径。原 Codex 图标的启动行为不变。退出、文件保存、带环境启动与真实连接验收分别报告。
