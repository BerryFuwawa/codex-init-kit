## 🌐 新增 WebSocket 线路修复

浏览器能用，Dot 却一直连不上？现在可以分开检查浏览器、模型回复和 Dot 远程连接，查看哪一步尚未完成。

默认沿用现有 HTTP 代理，也能给 Dot 单独填写代理 IP 和端口。确认后通过官方应用执行别名重新启动 Codex，让本次代理环境生效。线路检查和撤销入口都放在“连接与修复”中。[查看使用方法](WebSocket.md)

共用地址无需额外转发组件；独立地址才启用本机组件，随 Codex 退出，无需安装驱动或系统服务。独立线路按远程目标分流，模型回复保持原定代理路线。

## ✅ 这次验证了什么

桌面版 75 项隔离检查通过，覆盖正式规则写入、备份回滚、页面交互、代理分流和更新器。在本机共用 3067 代理的实测中，Chrome 测试页打开、读取和关闭成功；Dot 原生列表与读取均成功，没有使用备用读取方式。本机日志及自动诊断也确认远程连接已建立。

旧独立脚本继续保留。其原始编码命令入口此前被本机火绒系统加固拦截，本次没有修改防护规则或重新触发；桌面版实际使用的可读脚本入口已完成隔离验收。发送、长期稳定性、独立入口下的官方应用端到端测试及跨不同缩放实体显示器的验收边界见[验证报告](Validation-2.3.1.md)。
