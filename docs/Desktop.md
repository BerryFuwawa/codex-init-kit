# Codex Init Kit 中文使用手册（Windows）

保存代理后，从原来的 Codex 图标重开即可生效。电脑名称和允许控制可在 Codex 或 Work 中设置。[用户资料与 Work 设置](DesktopProfile.md)

初始化先检查差异，保留自定义配置，仅更新所选功能管理的内容。完整初始化开始前确认关闭 Codex，未完成项目可以单独重试。[初始化策略](NativeInitializationReconcile.md) · [配置何时生效](ConfigurationEffects.md)。

原生 WPF 中文桌面工具，集中管理 Codex 初始化、浏览器连接、组件修复、CLI 和备份。默认窗口约 1000 × 740，最小 800 × 540；小屏幕可滚动查看，支持 Windows 缩放。

本文对应桌面版 v2.3.10。[下载桌面版](https://github.com/BerryFuwawa/codex-init-kit/releases/latest) · [更新说明](Release-2.3.10.md)

## 遇到问题，先选哪项？

| 需求或现象 | 入口 | 处理范围 |
| --- | --- | --- |
| 查看当前配置 | 概览 → 刷新状态 | 只读状态检查 |
| 调整子代理并发数或恢复默认模型 | 初始化 → 模型设置 | 自动指派和手动指定共用并发数，确认初始化后保存 |
| 添加 Playwright CLI 或 Chrome DevTools MCP | 初始化 → 功能选择 | 按需安装、识别已安装的工具并单独卸载 |
| Dot／Remote 一直连接中 | 连接与修复 → 连接状态 | 保存代理并检查模型线路，Work 在线状态以实际连接为准 |
| 连不上 Chrome | 连接与修复 → 浏览器 | 组件、代理、环境检查及可恢复的入口修复 |
| 启动很慢，CUA 反复生成临时文件 | 连接与修复 → 电脑操作 | 对照当前官方组件检查，按需备份修复 |
| 无法启动、无法加载组织设置 | CLI 管理，或连接与修复 → 桌面启动 | 可尝试官方独立 CLI；启动组件修复针对 EPERM / rename_staging 等情况 |
| 配置提示失效字段 | 连接与修复 → 配置检查 | 先备份，再定向清理，不重置全部配置 |
| 更新或切换 CLI | CLI 管理 | 桌面原生与官方独立 CLI 分别管理 |
| 恢复历史配置或 CLI | 备份与回滚 | 选择版本和时间，核对确认后恢复 |
| 只改代理配置 | 连接与修复 → 连接状态 → 保存代理配置 | 备份并更新代理设置 |
| 查失败原因 | 日志，或连接与修复 → 诊断 | 中文说明与原始输出可切换 |

浏览器组件恢复后，从原图标重开 Codex，用独立测试标签页实际读取网页。账号、服务端及代理问题以实际结果为准。[浏览器说明](BrowserConnection.md)

## 初始化

1. 在“工作区与网络”选择工作盘和代理。端口行依次为“阁下的代理端口：”、填写框、软件预设、常用软件预设端口提示。预设自动填写且只读，自定义模式允许编辑；启动时从已有代理端口反选。
2. 在「功能选择」按用途勾选。子代理多线程首次使用时关闭，之后沿用上次保存的设置。Playwright CLI 和 Chrome DevTools MCP 可按需添加。[浏览器工具](Settings.md#浏览器工具) · [CLI 类型](#浏览器cli-与初始化顺序)
3. 在「模型设置」选择默认模型与父模型。启用子代理后，选择「自动指派」可让父模型按任务挑选子模型和思考强度，也可自己指定。右侧「最大并发数」默认 6 个。右下角的「恢复默认模型设置」可重置本页选项，确认初始化后保存。[模型设置说明](Settings.md#模型)
4. 查看变更摘要。开始时检查相关应用进程，检测到 ChatGPT／Codex 运行则询问是否关闭，默认取消。关闭会中断任务，请先保存工作。
5. 执行页显示真实阶段、当前活动、已处理项目数和耗时。百分比按已完成或已处理的阶段计算，阶段耗时可能不同。长时间任务不虚构预计剩余时间。执行详情可展开，部分完成时显示未完成项目。

点击「确认并开始初始化」后会弹出「正在准备初始化」。检查完成后，窗口会自动收起。如果 Codex 还在运行，工具会先请你确认是否关闭它。

进入执行页后可以切页，从概览点「开始初始化」可返回当前进度。Playwright CLI 首次安装完成后，可以选择设置浏览器或直接继续。全部成功后，点「启动 Codex」打开桌面应用，或点「关闭」留在结果页查看日志。部分完成时可在结果页重试未完成的项目。

初始化按需备份并合并配置与全局 AGENTS.md；原有权限、未知配置及未管理的自定义规则保留。项目内 AGENTS.md、已有记忆、对话和项目文件保留。取消某项规则后移除对应托管规则，已有笔记不会删除。[全部选项](Settings.md)

## 浏览器、CLI 与初始化顺序

执行顺序为前置退出检查及 CLI 复核 → 桌面更新 → 配置、目录与 CUA → 独立 CLI 更新 → 可选启动保护 → 应用所选 CLI → 浏览器组件检查 → 准备所选浏览器工具。

独立 CLI 缺失时按需准备，即使没有勾选更新。切换失败会尝试恢复初始化前的 CLI 路径设置；桌面更新仍在进行、包不完整或等待重启时暂停依赖步骤。可独立执行的步骤继续，最终报告完整完成、部分完成或失败。

CLI 管理分别提供更新官方独立 CLI和桌面版。独立更新不额外安装启动保护或登录任务。桌面原生 CLI 随官方 Store 桌面应用更新，不覆盖 WindowsApps 二进制；winget 仅精确更新目标包，不跨通道、不自动重启。

没有可用升级时显示当前软件源没有更新。内置 CLI 版本探针因 Windows 错误码 5 受限，而官方包和签名检查通过时，单独提示验证受权限限制。一般更新失败会说明可在微软商店或 Codex 内手动更新。[桌面启动故障处理](DesktopStartupRecovery.md)

## 备份、日志与更新

回滚列表显示初始化配置与保护器 CLI 的版本、时间和路径。未选择时回滚和打开文件夹不可用；删除所有回滚需单独确认，保留当前及被引用 CLI，删除后无法从这些备份恢复。

日志默认跟随底部，手动上翻暂停，回到底部或点击“回到最新日志”恢复。中文翻译在本地完成，原始内容保留。切换页面或中英文不清空阅读状态。[日志说明](Logs.md)

GitHub 请求顺序为官方 → 自定义 → 内置十个镜像。内置站点按当前资源并行检查，使用最快的有效站点，下载失败或已有校验失败时依次回退。代理设置仍生效，不改系统或 Git 配置。更新下载绑定仓库、版本、URL 和 SHA-256；退出后替换原 EXE 并重启，成功后清理旧版本。

## 动画与架构

连续滚动会衔接当前速度，鼠标移到输入框和日志区时也保持平滑。更新检查结束时保留当前页和阅读位置。导航、页签、按钮和状态提示使用同一套圆润图标。左侧和页头的圆角播放键都代表「初始化」。


雾夜蓝配色、统一控件和薄边框由 MorandiTheme.cs 与 Controls.xaml 管理；页面由 MainWindow.Pages.cs 组织，后台操作沿用现有接口。没有增加 WebView、网页运行时或第三方 UI 依赖。

页面进入、按钮按压、下拉和弹窗使用短时非线性过渡；快速重复操作从当前值衔接。只有正在执行的不确定进度使用活动动画。关闭 Windows 客户区动画后使用静态反馈，不依靠动画表达成功或失败。[设计说明](Design-2.3.0.md)

## 构建与验证边界

环境：Windows x64、.NET Framework 4.8、Windows PowerShell 5.1。通过 tools/Build-Desktop.ps1 编译；EXE 的 --verify 运行内嵌回归，--self-test 检查资源，--render-preview 导出示例页面。测试使用隔离 CODEX_HOME，不真实初始化、不关闭当前 Codex，不升级当前桌面应用。

主程序源码使用 MIT 许可；第三方规则许可单独保留，可从“关于与许可”查看。2026-11-13，火绒安全实验室已确认此前提交的 `Backdoor/Meterpreter.el` 检测为误报，说明近期病毒库更新后可排除，并将优化相关 PowerShell 系统加固提示。邮件未提供具体病毒库版本号；旧病毒库仍可能触发提示，v2.3.0 已在本机现有信任设置下通过正式构建、资源检查及完整隔离验收；不将其解释为旧病毒库已全部消除提示。v2.3.2 通过 132 项原生隔离回归、界面和模拟 WebSocket 检查；故障机离线，本轮未执行真实初始化或启动验收，见[验证报告](Validation-2.3.2.md)。
