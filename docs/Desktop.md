# Codex Init Kit Desktop 2.3.0

原生 WPF 中文桌面工具，集中管理 Codex 初始化、浏览器连接、组件修复、CLI 和备份。默认窗口约 900 × 660，最小 800 × 540；小屏幕可滚动查看，支持 Windows 缩放。

当前源码为 v2.3.0，发布验收尚未完成。v2.2.13 已转为草稿，公开更新清单暂时指向 v2.2.12。[公开版本](https://github.com/BerryFuwawa/codex-init-kit/releases/latest) · [v2.3.0 更新说明](Release-2.3.0.md)

## 遇到问题，先选哪项？

| 需求或现象 | 入口 | 处理范围 |
| --- | --- | --- |
| 查看当前配置 | 概览 → 刷新状态 | 只读状态检查 |
| 连不上 Chrome | 连接与修复 → 浏览器 | 组件、代理、环境检查及可恢复的入口修复 |
| 启动很慢，CUA 反复生成临时文件 | 连接与修复 → 电脑操作 | 对照当前官方组件检查，按需备份修复 |
| 无法启动、无法加载组织设置 | CLI 管理，或连接与修复 → 桌面启动 | 可尝试官方独立 CLI；启动组件修复针对 EPERM / rename_staging 等情况 |
| 配置提示失效字段 | 连接与修复 → 配置检查 | 先备份，再定向清理，不重置全部配置 |
| 更新或切换 CLI | CLI 管理 | 桌面原生与官方独立 CLI 分别管理 |
| 恢复历史配置或 CLI | 备份与回滚 | 选择版本和时间，核对确认后恢复 |
| 只改代理配置 | 连接与修复 → 浏览器 → 仅保存代理配置 | 单独备份重写代理设置 |
| 查失败原因 | 日志，或连接与修复 → 诊断 | 中文说明与原始输出可切换 |

浏览器补丁准备完成不等于真实连接成功。需要重启 Codex 后，用独立测试标签页实际读取网页；HTTP 403 仅表示服务可达。账号、服务端及代理服务问题需分别核对。[浏览器说明](BrowserConnection.md)

## 初始化

1. 在“工作区与网络”选择工作盘和代理。端口行依次为“阁下的代理端口：”、填写框、软件预设、常用软件预设端口提示。预设自动填写且只读，自定义模式允许编辑；启动时从已有代理端口反选。
2. 在“功能选择”按工作与规则、记忆、修复与连接、组件更新分类选择。子代理多线程仍位于最后，默认关闭；其他原有功能默认开启。CLI 默认沿用当前模式，手动选择优先。
3. 在“模型设置”继承或直接更换模型。未设置时父、子模型均为 gpt-6.1-sol / 中（medium）；子代理关闭时子模型置灰。模型是否可用取决于账号。
4. 查看变更摘要。开始时检查相关应用进程，检测到 ChatGPT／Codex 运行则询问是否关闭，默认取消。关闭会中断任务，请先保存工作。
5. 执行页显示真实阶段、当前活动、已处理项目数和耗时。百分比按已完成或已处理的阶段计算，阶段耗时可能不同。长时间任务不虚构预计剩余时间。执行详情可展开，部分完成时显示未完成项目。

初始化期间允许切页。概览“开始初始化”返回当前进度；完成、部分完成或失败后自动回到结果页，再显示明确提示。日志、阅读位置与文本选择保留，可继续查日志或重新设置。

完整初始化先备份配置与全局 AGENTS.md，再按所选功能重建；原全局自定义规则保留在备份里。项目内 AGENTS.md、已有记忆、对话和项目文件保留。取消某项规则后，后续初始化省略该规则，已有笔记不会删除。审批与沙箱使用 Codex 默认设置。[全部选项](Settings.md)

## 浏览器、CLI 与初始化顺序

执行顺序：前置退出检查及 CLI 复核 → 桌面更新 → 配置、目录与 CUA → 独立 CLI 更新 → 可选启动保护 → 应用所选 CLI → 浏览器修复。

独立 CLI 缺失时按需准备，即使没有勾选更新。切换失败会尝试恢复初始化前的 CLI 路径设置；桌面更新仍在进行、包不完整或等待重启时暂停依赖步骤。可独立执行的步骤继续，最终报告完整完成、部分完成或失败。

CLI 管理分别提供更新官方独立 CLI和桌面版。独立更新不额外安装启动保护或登录任务。桌面原生 CLI 随官方 Store 桌面应用更新，不覆盖 WindowsApps 二进制；winget 仅精确更新目标包，不跨通道、不自动重启。

没有可用升级时显示当前软件源没有更新。内置 CLI 版本探针因 Windows 错误码 5 受限，而官方包和签名检查通过时，单独提示验证受权限限制。一般更新失败会说明可在微软商店或 Codex 内手动更新。[桌面启动故障处理](DesktopStartupRecovery.md)

## 备份、日志与更新

回滚列表显示初始化配置与保护器 CLI 的版本、时间和路径。未选择时回滚和打开文件夹不可用；删除所有回滚需单独确认，保留当前及被引用 CLI，删除后无法从这些备份恢复。

日志默认跟随底部，手动上翻暂停，回到底部或点击“回到最新日志”恢复。中文翻译在本地完成，原始内容保留。切换页面或中英文不清空阅读状态。[日志说明](Logs.md)

GitHub 请求顺序为官方 → 自定义 → 内置十个镜像。内置站点按当前资源并行检查，使用最快的有效站点，下载失败或已有校验失败时依次回退。代理设置仍生效，不改系统或 Git 配置。更新下载绑定仓库、版本、URL 和 SHA-256；退出后替换原 EXE 并重启，成功后清理旧版本。

## 动画与架构

连续滚动会衔接当前速度，鼠标移到输入框和日志区时也保持平滑；拖动滚动条、按键和切页会停止原滚轮目标。更新检查结束时保留当前页和阅读位置。标题、分类、页签和常用操作使用统一的线性图标。


雾夜蓝配色、统一控件和薄边框由 MorandiTheme.cs 与 Controls.xaml 管理；页面由 MainWindow.Pages.cs 组织，后台操作沿用现有接口。没有增加 WebView、网页运行时或第三方 UI 依赖。

页面进入、按钮按压、下拉和弹窗使用短时非线性过渡；快速重复操作从当前值衔接。只有正在执行的不确定进度使用活动动画。关闭 Windows 客户区动画后使用静态反馈，不依靠动画表达成功或失败。[设计说明](Design-2.3.0.md)

## 构建与验证边界

环境：Windows x64、.NET Framework 4.8、Windows PowerShell 5.1。通过 tools/Build-Desktop.ps1 编译；EXE 的 --verify 运行内嵌回归，--self-test 检查资源，--render-preview 导出示例页面。测试使用隔离 CODEX_HOME，不真实初始化、不关闭当前 Codex，不升级当前桌面应用。

主程序源码使用 MIT 许可；第三方规则许可单独保留，可从“关于与许可”查看。公开源码与文件 SHA-256 不构成无病毒证明。火绒 Backdoor/Meterpreter.el 检测仍待官方复核；PowerShell 系统加固提示是另一类行为提示。v2.3.0 当前完整 EXE 生成后文件未能保留，可分发构建和在线更新验收尚未完成。
