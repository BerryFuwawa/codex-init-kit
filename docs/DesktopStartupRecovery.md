# 桌面版无法启动：检查启动组件

部分 Windows 用户遇到桌面版打不开或显示“无法加载组织设置”。如果近期桌面日志同时出现 `bundled_executable_relocation_failed`、`EPERM`、`rename_staging` 和 `codex.exe`，可能是桌面应用复制启动组件时失败。相关现象可参考 [Codex 社区问题](https://github.com/openai/codex/issues/57005)。组织设置错误也可能有其他原因，不应只凭提示文字判断。

1. 打开初始化工具，选择「维护恢复」→「桌面启动修复」→「检查启动问题」。检查会核对当前官方桌面包、启动组件及近期日志特征，不会修改启动组件。
2. 如果当前版本的组件目录缺失，先保存工作并彻底退出 Codex，再点击「修复桌面启动组件」。工具不会强制关闭当前任务或 Chrome。
3. 修复完成后正常启动 Codex，确认是否能打开。组件核对通过只说明文件已准备好，并不保证启动或浏览器连接成功。

工具只支持当前用户安装、身份和状态通过检查的 Microsoft Store 正式版。它从该版本的官方文件和启动逻辑计算目标目录，并复制和核对 `codex.exe`、`codex-code-mode-host.exe`、`codex-windows-sandbox-setup.exe`、`codex-command-runner.exe`。它不会套用其他用户或其他版本的目录名，不改写桌面应用安装目录、配置、会话和项目，也不会清理旧的暂存目录。

如果目标目录已存在但文件缺失、被修改或哈希不一致，工具会停止并显示目录，不覆盖已有内容；复制中途失败也会保留现场以便排查。遇到这种情况不要反复修复，请先检查日志、保存现有目录，或通过 Microsoft Store 修复／重新安装官方应用。若提示版本结构不支持、应用正在更新或仍在运行，先解决提示后再检查。若存在 `CODEX_CLI_PATH` 覆盖，工具会提示另行检查启动保护与 CLI 模式。

日志特征来自有限范围的近期日志，未检出不表示一定没有发生过该故障；日志可能属于旧版本。账号、网络、代理和其他配置问题需要分别排查。
