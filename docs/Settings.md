# Windows 版 Codex 初始化指南（工作目录、模型与代理）

打开 Codex Init Kit，点击「开始初始化」，选择工作盘和需要的功能。已经配置过 Codex 的用户，可以在确认页核对沿用的模型、CLI 和代理地址，再决定是否执行。

## 确认与执行

- 启动时同时继承 `CODEX_HOME/.env` 中的代理 IP 和端口，优先 HTTP_PROXY，其次 HTTPS_PROXY；支持 HTTP 入口的 IPv4／IPv6。端口继续反选预设。无配置时仍用 v2rayN 新版／10808。带认证、HTTPS 入口或域名等当前界面不支持的地址会提示，不自动转成其他地址，不修改原文件。
- 点击确认开始后，工作盘、代理、模型、CLI 和所有勾选项固定为本次快照。预检、关闭确认、授权与执行使用同一份；运行期间设置只读，日志和页面仍可查看。取消后恢复编辑。
- 概览显示已保存值，尚未执行的选项另列为待应用设置。确认页先展示可比较的差异，组件是否需要下载或修复在执行时检查。
- 状态查看、配置检查、回滚和本地组件检查不受未填代理端口影响。
- 相同内容跳过写入、最新组件跳过下载；完整初始化仍先询问关闭正在运行的 Codex。规则、未知配置和单项重试行为见[初始化策略](NativeInitializationReconcile.md)。

初始化保留登录与用户资料；电脑名称和允许控制可在 Codex/Work 中手动设置，不需要由工具恢复身份或选择资料目录。[用户资料与 Work 设置](DesktopProfile.md)。

初始化依次配置「网络与转发」和「功能选择」。开启文件夹管理时，在「工作区与目录」选择工作盘，再进入「模型设置」。已有可用工作盘会自动回填，首次使用请手动选择。

## 代理开关

「初始化」页面的 HTTP 代理默认开启。端口行按「阁下的代理端口：」「端口填写框」「下拉菜单」「常用端口预设」提示标签排列。提示标签带信息图标，悬停可查看预设与自定义端口说明。选择软件会代填常用 HTTP／混合端口，填写框变为只读；选择最后一项「自定义代理端口」可填写 `1–65535` 的整数。IP 留空使用 `127.0.0.1`。

| 下拉选项 | 常用端口 |
|---|---:|
| v2rayN 新版 | 10808 |
| v2rayN 旧版 | 10809 |
| Karing | 3067 |
| Karing 全代理入口 | 3066 |
| Clash Verge Rev | 7897 |
| Clash／Mihomo 常见配置 | 7890 |
| Hiddify | 12334 |
| NekoRay | 2080 |
| 自定义代理端口 | 手动填写 |

打开工具时，先读取当前用户 `CODEX_HOME/.env` 中 `HTTP_PROXY` 的端口，缺失或为空时再读取 `HTTPS_PROXY`。端口匹配预设就选中对应项，否则选中自定义并保留原端口。没有已有配置时默认选中 v2rayN 新版，显示 `10808`；此时首次选择自定义，填写框为空。读取失败或已有端口无效时显示提示，并使用空白自定义输入框。

已有自定义值和本次输入会在切换预设或页面时保留。初始化和「连接与修复」→「连接状态」页共用同一组代理控件。启动自动检查更新前已完成端口读取。界面选择在确认并执行对应操作后写入现有配置，下次打开再按保存的端口选择预设。

取消勾选后不需要填写端口。执行初始化或「连接与修复」→「连接状态」中的「保存代理配置」时，将关闭本工具管理的 Codex 代理配置。修改开关本身不会立即改写 Codex 配置；需确认并执行操作。本工具自己的更新请求也遵循开关。

例如本机 V2RayN 可填端口 `10808`、IP 留空；软路由可填它提供的端口，例如 `7890`，IP 填路由器地址，例如 `192.168.1.1`。支持 IPv4 和 IPv6。IP 栏只填地址，不填 `http://` 或端口。代理服务需要已开启且允许当前电脑连接；此工具不负责启动代理服务。

## 可选功能

功能区分为「工作习惯」「开发习惯」「修复与连接」「组件更新」。重新打开工具会沿用工作和开发习惯的勾选。子代理多线程和浏览器工具位于分类区下方，再往下可选择 CLI 类型。

常用初始化功能默认勾选。子代理多线程和浏览器工具可按需开启。

- 文件夹管理功能：创建标准工作目录、设置无项目任务目录和目录管理规则。
- **本机凭证管理**随文件夹管理一起默认开启。初始化会写入规则，指导 Codex 使用工作区下 `Config\Credentials\索引.md` 和索引登记的本机助手。保存和登录需要提前准备对应的索引与助手。关闭本功能后再初始化，会移除工具写入的凭证管理规则。
- 防止过度防御：将 HERO 中文完整规则和实现、防御、自主交付边界写入全局 `AGENTS.md`，默认勾选；[查看完整说明](AntiOverDefense.md)。
- **按需笔记与文档管理**引导 Codex 整理 Markdown 笔记、文档和索引。
- **优先使用命令行**引导 Codex 先使用可靠的专用 CLI 或 PowerShell。
- **开发时参考开源案例**默认勾选。开发新功能时，Codex 会参考 GitHub 的类似做法，自行决定复用或自己实现。取消并再次初始化会移除这一条规则。
- 启用 Codex 记忆：默认开启本地记忆生成与使用；取消后关闭，已有记忆文件保留。设置在完整初始化时写入，不修改项目文件和对话记录。
- CLI 启动保护与修复：检查／准备启动组件，安装登录维护任务。
- CUA 检查与修复：检查电脑操作组件，异常时修复。
- 浏览器组件检查与修复：校验并按需恢复官方原始组件，保留未知入口修改；真实连接单独验收。
- 更新官方CLI：更新官方独立 CLI 组件，保留当前 CLI 模式，不单独安装登录维护任务。
- 更新桌面版（含原生CLI）：先通过 winget 更新当前官方 Microsoft Store 桌面包，原生 CLI 随应用更新。
- 子代理多线程：保留当前对话的父模型。选「自动指派」时，父模型为每个子任务选择可用模型和思考强度；选具体子模型时，使用你保存的档位。
- 最大并发数：在「模型设置 → 子模型」填写允许同时工作的子代理数量，默认 6 个，父模型单独计算。自动和手动指派共用这个数，保存后下次打开会沿用。开启子代理时使用 V2。

功能列表下方的两个按钮选择初始化后使用的 CLI，更换类型须完成完整初始化。默认沿用检测到的桌面版原生 CLI 或官方独立 CLI，确认页会显示选择来源。刷新状态或返回修改时保留手动选择。独立组件缺失时会按需准备。

登录检查、组件维护和卸载启动保护都会保留当前选择。发现组件缺失时，可先修复组件；要改用另一种 CLI，请完成初始化。

执行顺序为应用退出检查 → 桌面更新 → 配置、目录及 CUA → 独立 CLI 更新 → 可选启动保护 → 应用并核验所选 CLI → 浏览器组件检查。点击确认并开始初始化后，工具会检测桌面应用和关联运行时。检测到正在运行的 ChatGPT／Codex 时，需先保存工作，再选择“关闭并继续”或“取消”。同意后直接强制结束已经核验并获授权的桌面及关联进程，按原始快照确认全部目标退出后继续初始化；父进程退出后的授权子进程仍会跟踪。独立 CLI、路径不符或其他用户／会话的进程不作为结束目标。自然退出的进程会跳过，应用重新启动、权限不足、身份无法核验或等待超时时会显示原因。关闭会中断正在执行的任务。取消会返回确认页并保留选择。切换失败时尝试恢复初始化前的用户 CLI 路径设置，并显示未完成原因。桌面更新待完成或要求重启时暂停依赖修复和 CLI 切换。代理选项也与「连接与修复」→「连接状态」页双向同步。详见[浏览器故障处理](BrowserConnection.md)。

初始化会先备份需要修改的文件，再合并所选配置和规则。子代理多线程关闭时，工具会关闭 V2 子代理并移除它管理的子代理规则。项目目录中的 `AGENTS.md` 和自定义内容会保留。仅需单项操作时可进入「连接与修复」或「CLI 管理」。

## 浏览器工具

在「初始化 → 功能选择」勾选需要的工具。两项默认关闭。

- **Playwright CLI** 可以点击、填表和读取网页。扩展是可选的。点 Edge 或 Chrome 会打开对应浏览器的扩展安装页。点 Firefox 并确认后，才会下载 Playwright 专用 Firefox。已安装 Playwright CLI 时，可随时从它右侧的「浏览器设置」打开这组选项。
- **Chrome DevTools MCP** 使用本机已安装的 Chrome，用于查看网页报错、网络请求和加载性能。

已安装的项目会显示「已安装」，重新初始化会跳过。可以从该项右侧单独卸载，已安装的日常浏览器会保留。

## 按需笔记与文档管理

默认勾选。简单问答直接回复。任务中出现值得日后查证、复用或交接的信息时，Codex 可主动建立或更新 Markdown 笔记。临时目标、约束、决定、验证结果、路径和待办记入任务笔记。长期有用的操作方法、设计决定和排查经验补进项目现有文档。

失败记录保留尝试过的方法、当时条件、已确认的原因和验证过的替代方案。原因尚未确认时标为待查。需要单独整理时可在任务子目录建立 `工作记录.md`。资料较多或分散时用 `索引.md` 列出相对路径和一句用途。

当前任务需要核对旧决定、验证结果或路径时，再通过索引查阅相关段落。上下文压缩本身不会触发回读。取消勾选后，下次初始化省略此规则，已有笔记、文档和索引会保留。

## 优先使用命令行

默认勾选。有可靠的专用 CLI 时优先使用。Windows 文件操作、系统查询和批量操作优先用 PowerShell，由 Codex 在已有授权和权限内执行并核验。缺少可行的命令行路径时才考虑操作界面。确需本人授权或验证时，Codex 应说明你需要配合的最小一步。

## 模型

在「初始化 → 模型设置」中，**默认模型与父模型**控制新对话使用的默认模型和思考强度。工具打开时沿用已保存的全局设置，首次使用默认选 GPT 6.2 Sol，思考强度为中（Medium）。

首次使用时，「功能选择 → 子代理多线程」默认关闭。开启后，可在**子模型**一栏选择指派方式。

- **自动指派**是默认选项。父模型按任务选择子模型和思考强度，强度栏显示「由父模型决定」。
- **手动指定**时，先选择子模型，再选它的思考强度。
- **最大并发数**是允许同时工作的子代理数量，默认 6 个，父模型单独计算。自动和手动共用这个数，实际启用多少个由任务决定。确认初始化后，下次打开会沿用开关、指派方式和并发数。

点击卡片右下角的「恢复默认模型设置」，父模型恢复为 GPT 6.2 Sol、强度中（Medium），子模型恢复为「自动指派」，最大并发数恢复为 6。多线程关闭时也可恢复这组值，子模型选项仍会置灰。确认初始化后才保存本次改动。

父模型和子模型都先列出本机 Codex 缓存中的型号，再补上工具自带的型号，例如「GPT 6.2 Sol（内置）」。同一型号只列一次，优先使用本机记录的思考强度。没有可读取的缓存时，工具提供的型号都会标为「内置」。实际可用性取决于账号和客户端。

已隐藏或停用的型号不会补回，已配置的自定义模型可以继续使用。恢复默认时，如果本机模型列表里有其他可用型号，却没有 GPT 6.2 Sol，会选中首个本机可用型号。也可以手动选择带「内置」的型号，确认初始化后保存。

| 模型 | 可选思考强度 |
| --- | --- |
| `gpt-6.2-sol`、`gpt-6.2-astra`、`gpt-6.1-sol`、`gpt-6-astra`、`gpt-6.1-terra`、`gpt-6-sol`、`gpt-5.6-sol`、`gpt-5.6-terra` | `low`、`medium`、`high`、`xhigh`、`max`、`ultra` |
| `gpt-6-luna`、`gpt-5.6-luna` | `low`、`medium`、`high`、`xhigh`、`max` |

点击「检查所选配置」可核对模型和强度组合。确认页会展示本次所选模型、代理状态和功能开关。模型调用权限取决于账号和客户端。[Codex 与 Work 模型说明](https://learn.chatgpt.com/docs/models)

## 全局规则合并

全局 `CODEX_HOME\AGENTS.md` 保留未管理的自定义内容。工具负责中文 RTK 正文、基础工作规则及所选规则块；对应内容相同时跳过写入，需要修改时先备份。取消可选规则会移除该托管块，项目目录内的 `AGENTS.md` 不受影响。可在“备份与回滚”恢复本次备份。

## RTK 匿名统计与第 2/5 阶段卡住

v2.1.4 会在 RTK 集成前自动运行 `rtk telemetry disable` 关闭匿名统计，并关闭后台命令的标准输入，避免隐藏的 `Enable anonymous telemetry? [y/N]` 提示造成等待。关闭统计失败时会停止初始化，提示查看本次备份会话的 `rtk-telemetry.log`。

如果旧版任务已经卡住，先停止对应初始化任务，避免重复点击；在 PowerShell 终端运行 `rtk telemetry disable` 后，使用 v2.1.4 或更新版本重新初始化。新版不会自动终止已存在的旧版任务。

## 配置兼容警告

v2.1.5 可从「维护恢复」运行「检查配置」，再按需「清理已废弃配置」。清理仅针对 `features.code_mode_tool_description_first` 和 `features.guardianv2.thread_context` 的可靠布尔赋值，先备份原文件并生成 `Restore.ps1`；保留 Guardian 其他设置，不重置模型、代理或全局规则。

`session-flags` 提示来自会话参数时，文件中可能根本没有对应设置，删除文件内容不能消除该提示。配置检查会说明这个边界，不会把“文件中无需清理”当作“全部修复”。无需为了这两个警告执行完整初始化。详细步骤、扫描范围和恢复方法见 [配置兼容检查](ConfigCompatibility.md)。

## 记忆配置

“启用 Codex 记忆”位于「工作习惯」卡片内，默认勾选。初始化将 `[features] memories`、`[memories] generate_memories` 和 `use_memories` 同步写为所选布尔值。不会清空 `CODEX_HOME\memories` 或改写记忆模型、整理周期和配额阈值。生成记忆可能使用 Codex 配额，实际生效取决于当前客户端和账户设置。[官方说明](https://learn.chatgpt.com/docs/customization/memories)

## GitHub 下载设置

在“更新”页设置并保存，请求顺序为官方、自定义、内置十个镜像。自定义前缀可留空，内置镜像并行测速。关闭后仅使用官方地址。设置与初始化中的 HTTP 代理相互独立。[查看完整说明](GitHubMirrors.md)

## 持久网络配置

代理同时写入原生 CLI 的 .env 与 Windows 当前用户环境，并启用官方 Node 代理开关。其他遵循代理变量的当前用户程序也会读取这些设置。保存工作并从原图标重新打开后，分别验收模型、Work、桌面 WebSocket 与浏览器。[使用与覆盖范围](PersistentNetwork.md)
