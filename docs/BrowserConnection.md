# 浏览器连接检查与修复（2.2.2）

用于排查 Codex 连不上 Chrome，尤其是本机或软路由 HTTP 代理没有传入浏览器控制进程的情况。它不会启动代理软件，也不会关闭 Chrome 或你的标签页。

本版本包含 [PR #3](https://github.com/BerryFuwawa/codex-init-kit/pull/3) 的新版运行时定位与分块哈希兼容；当官方结构不能唯一识别或校验时，工具会停止并提示，不会猜测路径或覆盖文件。

## 使用步骤

1. 打开「浏览器连接」，核对代理开关、IP 和 HTTP／混合端口。这里与初始化页面同步；IP 留空使用 `127.0.0.1`，端口默认 `10808`，应按自己的代理设置修改。
2. 点击「检查连接」，查看组件完整性、代理端口可达性和环境继承探针。检查不会修改浏览器运行时，检查记录保存在本工具数据目录。
3. 需要修复时，保存工作并彻底退出 Codex，再从独立的 `CodexInitKit.exe` 点击「修复并启动 Codex」；也可点击「修复连接」后自行启动。Codex 或对应运行时仍在运行时，操作会停止，不会强制结束任务。
4. 程序请求启动 Codex 后，点击本工具的「复制连接测试指令」，在新对话中运行。指令要求新建独立测试标签页，访问 `https://example.com`，读取标题及页面内容，最后关闭本次测试标签。

「修复已准备」表示文件和环境准备完成。只有重启后通过浏览器工具成功打开页面、读取内容，才能说明真实连接已通过。当前版本不会自动把准备结果升级为“Chrome 已验证”；请保留新对话的实际测试结果。HTTP 403 只能说明对应 HTTP 服务有响应，不能证明 Chrome、账号认证或页面读取成功。端口检查只验证 TCP 可达性。

## 修复做了什么

从当前安装的官方 Microsoft Store 包读取运行时来源及启动算法，计算当前所需的运行时 ID，并定位唯一的 `cua-repl.mjs`。不使用其他电脑的用户目录、固定运行时 ID 或代理端口。

核对受支持的官方入口结构、当前完整组件和 bundled Node 的环境代理能力后，在原导入和 `launch()` 之间写入用户选择的 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`、`NODE_USE_ENV_PROXY`，并合并 `NODE_REPL_UNTRUSTED_ENV_ALLOWLIST`。原导入、启动和异常处理保留。环境探针实际运行隔离的 Node 子进程，验证变量继承；它不能代替真实 CUA 沙箱和 Chrome 的验收。

备份与记录位于：

```text
%LOCALAPPDATA%\CodexInitKit\Desktop\BrowserConnection
```

记录包括应用版本、包身份、源和目标路径、运行时 ID、代理地址及原始／修改后 SHA-256。原文件按字节备份；写入采用同目录临时文件和原子替换。重复修复不会叠加注入，代理改变时会从已校验的原始字节重新生成。

CUA 检查只接受能从官方源、备份和代理设置重新生成并核对哈希的受管理补丁。CUA 修复其他损坏组件后，会重新应用当前版本已校验的补丁。浏览器操作与 CUA 共用互斥锁，避免同时改写。

## 直连与恢复

- 关闭代理后点击「修复连接」，会恢复本工具管理的原始入口，不注入代理变量。
- 点击「恢复原始文件」，核对当前入口、官方源和备份哈希后恢复原始字节；原本没有补丁则不改写。
- 未知入口结构、第三方修改、备份或记录哈希异常时停止覆盖，显示未完成原因。不要为了消除提示手动改掉校验记录。
- 应用更新更换目录或运行时后，需要重新检查。不会将旧版本文件覆盖到新版本。旧备份会保留，当前版本只处理它自己的入口。
- 浏览器补丁恢复与初始化回滚、CUA 目录备份、CLI 保护器回滚是不同操作。

如果组件检查失败，先退出 Codex，在「维护恢复」运行 CUA 检查与修复；若提示未知版本或第三方改动，请保留日志和备份排查。无法连接代理时先检查代理软件、IP、端口和局域网访问设置。组件检查通过仍连接失败时，可更新桌面版和官方独立 CLI，或按概览引导切换 CLI；这些操作不能保证解决账号、服务端或浏览器扩展故障。

## 本次验证边界

自动回归覆盖变量传递、白名单保留、子进程继承、重复修复、代理关闭、字节回滚、未知结构、哈希及版本异常，以及 CUA 修复兼容。桌面更新使用模拟测试，不更新开发时正在运行的 Codex。

本次开发没有退出当前 Codex 执行实际运行时修改、重启和 Chrome 连接验收，也没有关闭用户标签页。因此，本次发布未宣称完成“应用补丁并重启后的真实 Chrome 验收”。
