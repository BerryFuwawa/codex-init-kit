# 浏览器组件与连接

在“连接与修复 → 浏览器”点击“检查组件”，只读核对当前官方应用对应的电脑操作运行时。组件完整性与真实 Chrome 连接分别验收。

## 修复组件

组件缺失或与官方源不一致时，可先保存工作并退出 Codex，再选择“修复组件”。工具备份原运行时目录，恢复当前官方版本的原始文件，并校验复制结果。

已识别的旧浏览器代理补丁会恢复为官方原始入口。识别要求当前官方源、旧记录、原始备份及补丁内容一致；未知入口修改会保留并提示。修复失败时恢复原目录。

## 验证连接

使用原来的 Codex 图标打开应用，在对话中运行页面提供的测试指令：新建测试标签，访问 example.com，读取标题和 DOM，再关闭本次新建标签。已有 Chrome 标签保留。

文件检查通过只说明组件完整。HTTP 状态码、代理端口可达或模型探针通过，都不能代替真实浏览器控制验收。

首次浏览器控制需要完成工具初始化。初始化和打开网页分开执行，读取以实际返回的网页标题、正文为准。若旧测试标签提示 `Debugger unattached`，在同一 Chrome 中新建独立测试标签验证，保留其他页面。浏览器控制会话的超时不等于组件损坏。

## 网络设置

CLI 代理在“连接状态”或初始化中保存到官方运行时读取的 .env。浏览器使用自身网络路径，CLI 配置不能证明浏览器已采用相同代理。当前源码不再向浏览器入口写入代理环境，也不提供修复后启动应用的专用入口。[网络范围与配置来源](PersistentNetwork.md)
