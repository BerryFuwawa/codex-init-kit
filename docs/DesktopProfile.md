# 保持原来的 Codex 和 Work 连接

初始化和后续启动自动沿用已确认的 Codex 资料与连接设置。普通用户无需查看资料目录、身份文件或选择启动参数。

## 用户点击流程

正常使用：点击初始化 → Codex 正在运行时确认关闭 → 完成后点“启动 Codex（使用本次设置）”。如果桌面已关闭且有有效观测记录，直接启动，不再出现资料选择或启动成功确认弹窗。

出现重复连接：打开“连接与修复”中的“原连接不见了？”，点击“恢复原来的 Codex”。有可靠旧记录时自动确定恢复目标，只确认关闭与恢复连接的影响。当前已经与旧记录一致时，提示无需切换。

缺少可靠旧记录时，工具提示先保存工作，从平时使用的图标重新打开 Codex，确认原 Work 连接上线，再点“沿用当前 Codex”。这条路径不需要重新执行完整初始化。它依赖一次实际连接确认，不依据目录名称或最后修改时间猜原身份。

## 验收场景

| 场景 | 预期行为 |
| --- | --- |
| 已有正常实例 | 从当前官方桌面进程树识别实际资料；关闭确认后保存，启动沿用 |
| 重复初始化 | 原资料与身份文件保持一致；可靠原记录不被另一套实例覆盖 |
| 实例已关闭 | 原目录与身份文件状态仍有效时自动续用已观测记录，不要求选择路径 |
| 记录失效且有可靠运行实例 | 普通初始化依据当前实际实例重新识别；确认关闭前保存，保留现用资料 |
| 记录失效且无运行实例 | 简短提示从平时图标打开后重试；停止相关启动 |
| 多个实例使用同一套资料 | 按既有进程授权统一关闭，保留同一套资料 |
| 多组实例使用不同资料 | 停止，不自动关闭或猜选；提示保存工作、只保留平时使用的一组 |
| 启动失败或实际资料不符 | 不报告成功，不自动重复启动、换目录或关闭已启动窗口 |
| 已有双连接且存在可靠旧记录 | 恢复目标取旧记录；当前实例与目标分别核验，确认后关闭当前实例并启动旧目标 |
| 已有双连接但缺少旧记录 | 提供“原图标打开并确认旧连接 → 沿用当前 Codex”的路径，保留两条连接记录 |

## 证据与保存

可靠证据来自当前用户会话中官方桌面子进程实际采用的 --user-data-dir；主进程请求参数不能单独充当实际采用证据。支持同一官方产品的旧版本仍在运行的实例。

预检只读取，取消不会保存。后台关闭前重新核对已确认的实例和实际资料，然后保存 LocalAppData/CodexInitKit/Desktop/desktop-profile.json。记录包含目录、采集时间、主进程身份及执行器身份文件的存在状态和文件时间，不保存身份内容或原始命令行。

已观测记录只要原资料和身份文件状态有效，就可继续使用，不按经过时长机械失效。记录缺失、损坏、目录消失或身份文件状态变化时，必须重新取得运行实例证据；恢复旧连接仍要求旧目标有可靠依据。

发现当前实例与有效旧记录不一致时，普通初始化或启动停止并提示恢复入口。恢复操作分别复核旧目标和当前待关闭实例，任何一方变化都停止；关闭当前实例不会将其资料覆盖进旧记录。

## 启动与确认

启动传递 --user-data-dir、CODEX_ELECTRON_USER_DATA_PATH、所选代理和最新保存的 CLI 环境。启动后再次观察实际采用的资料目录及已有身份文件状态，只有一致才记录启动成功。

普通无实例启动由用户点击直接发起；关闭现有桌面时保留确认。恢复旧目标即使当前桌面已关闭，也会提醒旧远程请求可能继续执行并要求确认。确认默认取消，主界面不展示或要求用户判断内部目录；诊断日志保留技术证据。

本地资料核验与 Work 服务端连接上线分别报告。执行器身份由官方桌面管理，工具不复制、重置或修改身份，不删除连接，不重新配对或注册。

## 已知限制与实机恢复

2026-11-16 已在官方桌面 26.1111.2228.0 上完成两次受控启动：原 Windows 入口恢复既有资料；共用启动核心随后同时传入两个目录参数，实际仍采用同一资料和旧 Work 环境。用户确认原电脑记录在线、新记录离线。已验证该版本的这条启动路径；其他版本和所有界面入口仍需分别验收。事后核验不能保证官方运行时在核验前没有产生自身注册行为。

没有旧观测的历史双连接，需要用户通过平时使用的入口及 Work 中的原连接做一次实机确认；软件不能补造缺失证据。有可靠旧观测时，受控恢复通常只需一次退出和启动；没有旧观测时，可能先从原图标打开，再沿用已确认的当前实例带代理启动。

实机操作前应保存工作，明确未结束的远程请求的远端状态，或由用户接受恢复连接后旧请求可能继续执行。关闭会中断对应桌面中的全部本地对话、Local Work 执行器及远程连接。两次实机退出启动已经获得明确授权并执行完毕。已有超时请求的终态仍可能无法确认，不应因连接恢复就重复发送。
