# 配置兼容检查与定向清理（2.1.5）

设置页出现“未识别配置”或“已废弃并忽略”时，先检查来源，无需完整初始化。

## 两类警告

| 提示 | 处理方式 |
| --- | --- |
| `features.code_mode_tool_description_first is ignored` | 文件内存在时可定向清理；来源是 `session-flags` 时，需检查桌面客户端与 CLI 的版本兼容性，文件清理不能移除客户端传入的参数 |
| `[features.guardianv2].thread_context is deprecated and ignored` | Codex 已自动启用线程上下文；仅移除 `thread_context`，包含 profile 覆盖，保留 Guardian 其他设置 |

命令行或会话覆盖与文件配置是不同来源。官方配置层次和 profile 说明见 [Config basics](https://learn.chatgpt.com/docs/config-file/config-basic)。本工具不会修改官方应用文件、自动切换 CLI 或关闭当前 Codex。

## 使用步骤与检查范围

1. 打开「维护恢复」→「配置兼容检查」，点击「检查配置」。此步骤只读。
2. 默认检查 `CODEX_HOME/config.toml`（未设置时为 `~/.codex/config.toml`）及同目录的 `*.config.toml` profile 文件，也识别文件内旧式 `[profiles.<名称>...]` 覆盖。
3. 如果需要检查某个项目，在项目目录框填写该项目路径。只额外检查这个目录的 `.codex/config.toml`，不遍历历史项目，也不自动检查其父目录配置。
4. 结果显示文件、行号和是否可以自动清理。点击「清理已废弃配置」并确认后，工具重新读取当前文件，先备份，再移除可靠识别的两项布尔赋值。
5. 重新启动 Codex，确认提示是否消失；工具不会替你关闭当前任务。

只有独立的 `true` / `false` 赋值可自动清理。点分键和普通带引号的键可识别；注释、多行字符串、相似键和其他 Guardian 设置保留。内联表、数组表、语法不完整、非 UTF-8 或链接路径等不支持的写法会提示手工处理。当前文件被其他程序修改时会停止，避免覆盖新内容。

检查全部 profile 文件不代表这些 profile 当前都启用。未找到旧项时会显示“文件中无需清理”，这不代表会话参数警告已经修复；继续检查对应来源或未包含的配置层。

## 备份与恢复

备份保存在现有「Codex初始化备份」目录下独立的 `ConfigCompatibility-时间-随机编号` 文件夹内，具体路径显示在结果和日志中。每个文件保留原始字节，并生成 `Restore.ps1` 记录原路径。无可清理项时不创建备份或改写文件。

恢复前保存任务并关闭 Codex，确认备份属于本次操作，然后在 PowerShell 运行该备份目录里的 `Restore.ps1`。恢复会覆盖这些原路径上的当前配置；如果清理后又做了其他修改，先另存当前文件。

读取、备份或写入失败时操作会报告未完成。多个文件处理中若部分已成功，原始备份仍保留，可用同一恢复脚本恢复。此备份与完整初始化回滚相互独立。
